## 1. Bugs and data-integrity issues

### 1.1 `move_block` leaves `plannedMinutes` stale
I moved *LithOS: Read pass (2 of 3)* from 09:00–09:55 to 06:45–07:25. The response said `minutes: 40` but kept `plannedMinutes: 55`.
- **Effect:** Workload and the day score compare actual time against 55 minutes when only 40 can fit, so the day looks worse than it really is.
- **Fix:** when a block's length changes, set `plannedMinutes` to the new length (or to `min(old, new)`).

### 1.2 Past blocks still show `status: "upcoming"`
Today's five reading sittings (05:30–11:25) came back as `status: upcoming, timing: past` with no focus time recorded.
- **Fix:** add a `missed` status, set when a block's end time passes with no focus time logged. Show missed blocks in the wrap-up and include them in catch-up hours explicitly. At the moment it isn't clear which blocks the 26.5 h catch-up figure is made of.

### 1.3 Calendar sync side effects aren't visible
Adding one block to an unplanned Monday caused FocusOS to build that day and returned `Pushed to Google Calendar (16 created, 0 updated, 9 removed)`. Nothing said which 9 events were removed.
- **Fix:** return the titles and dates of anything created or removed outside the day being edited. Never remove events that FocusOS didn't create. Add a `dryRun` option to calendar pushes.
- **Partly addressed (2026-11-28):** the push response now separates changes on other dates and states that only events FocusOS created are ever removed. It still doesn't list which events changed: one move this morning reported "25 updated" on other dates with no titles. *(Later the same day: created events are now listed by title; updated and removed ones still aren't.)*

### 1.4 A pass can be marked "done" with nothing in it
- LithOS pass 1 is marked `done` with 55 minutes logged, but all four checklist steps are `false` and `contributions: []`.
- The Agentix pass 2 was closed in 1 minute with the note "Done already" and no key points.
- **Fix:** before closing a pass, require a minimum output (at least one contribution for a Skim; 3 or more key points for a Read), or close it as `done (thin)`. The weekly gap search currently relies on pass outputs that don't exist.

### 1.5 Missed blocks can't be cleared, so rescheduling duplicates them *(found 2026-11-28)*
I rescheduled Saturday to start at 9:00. The blocks from 05:30 to 07:25 had already passed, so `move_block` and `remove_block` both refuse them. The only option was to add new copies, which leaves two "LithOS: Read pass (1 of 3)" and two "(2 of 3)" blocks on the same day. The early ones still count as required minutes.
- **Fix:** add `skip_block` or `reschedule_block(date, slotId, newStart)` that marks the original as skipped (so it no longer counts toward Workload) and carries its title and objective over to the new time.
- This also confirms 1.1: the LithOS wrap-up moved into a 40-minute slot still reports `plannedMinutes: 55`.

### 1.6 Workload calls a day "overrun" when it simply followed the plan *(found 2026-11-28)*
On Saturday I planned about 8 reading sittings and worked them: 307 focus minutes by 17:35. Workload says **Overrun (2.06×)**, because required is only 149 minutes. Reading and admin blocks are left out of required. Only deep_work blocks, revision due, assessment prep and the daily share of course/goal targets count.
- **Effect:** a day spent on the planned paper reading looks like overwork, and a day that skips planned reading can still look on track.
- **Fix:** count planned blocks that have a paper or goal objective (and reading blocks generally) in required, or keep them in a separate "planned" bar. "Overrun" should mean more than *planned*, not more than *the goal's daily share*.

### 1.7 Goal pace ignores paper reading *(found 2026-11-28)*
`goalPaceWarnings` says "Nothing planned or logged for Literature / SOTA track this week", but this week has about 5 h of focus time on LithOS and Janus. Both are papers named in that goal's milestones.
- **Fix:** count focus time on papers linked to a goal (or named in its milestones) toward that goal's weekly hours. Let papers carry a `goalId`.

## 2. Gaps in the MCP server

### 2.1 Link blocks to papers
`add_block` accepts `taskIds` but has no way to point at a paper pass. The blocks I created for LithOS and Janus are plain `reading` blocks. The app's own blocks carry `objective: {kind: "paper", id, passNo}`.
- **Effect:** focus time in those blocks won't count toward the paper's Reading time or pass progress.
- **Fix:** add `objective: {kind: "paper", paperId, passNo}` (and `revisionQueue` / `readingHabit`) to `add_block`.

### 2.2 Batch and range operations
Moving 13 blocks into the mornings took 13 calls, sent in a particular order so that no move collided with a block still in its old spot.
- **Fix:**
  - `apply_plan(date, blocks[])`: set the whole editable layer of a day in one atomic, validated call.
  - `shift_blocks(date, from, to, offset)`: move a range of blocks together.
  - `add_session(date, start, totalMinutes, title, objective)`: split a long session into sittings automatically, with breaks, titled "(1 of n)".

### 2.3 Recurring blocks and commitments
"Read daily updates" had to be added one day at a time. `add_block` explicitly refuses commitments.
- **Fix:** add `create_commitment` / `update_routine` (title, type, days of the week, time, duration) so standing habits can be set up from chat.

### 2.4 Tentative and one-off meetings
The meeting with NGS Sir ("time TBC, probably afternoon") had to be entered as a `custom` block plus a separate task.
- **Fix:** add a `meeting` block type with `tentative: true`, an optional time window ("afternoon"), and attendees. Treat tentative blocks as soft, so planning can still use that time.

### 2.5 Defer or snooze revision
Removing the revision blocks left 3 cards due, and there's no tool to push them back.
- **Fix:** add `defer_revision(date | days)`, and a per-day "no revision" flag for crunch days.

### 2.6 Compact responses
`get_week` repeats the same six routine blocks (sleep, meals, gym) for every day.
- **Fix:** add `compact: true`, which returns the routine once and then only the blocks that differ per day.

### 2.7 Commit the weekly plan from chat
This week's plan shows `committed: true, replans: 5, proposedBlocks: []`. Next week's shows `committed: false`, and there's no tool to commit it.
- **Fix:** add `commit_week(weekStart)`, and have the week plan record blocks added through MCP.

## 3. Planning features

### 3.1 Day-shape preference
I asked for "mornings busy, evenings easy". There's no setting for this, so the blocks had to be moved by hand.
- **Fix:** add per-day-part energy windows (for example deep work 05:30–13:00, light work 13:45–18:00, no work after the gym). The weekly planner and Up next should fill the deep windows first and never put deep work in light windows.

### 3.2 Hard-deadline alerts
The IndiaAI fellowship (`kind: external`, due 30 Nov) is excluded from Workload, so nothing in the plan pushed for it, and it had no time blocked even with 3 days left.
- **Fix:** when an external task is due within N days (default 3) and has no blocks, show a banner and offer to schedule it. Let external tasks carry `estimatedSessions` even though they stay outside Workload.

### 3.3 Reading-habit sittings should name a paper
"Reading (n of 15)" sittings took whole mornings, but nothing tied them to a specific paper or pass.
- **Fix:** have each habit sitting pick the next pass from the paper queue (by priority, then deadline) and show it in the title, e.g. "Reading: LithOS pass 2". Let the person change the pick in one click.

### 3.4 Lead-up to a deadline or meeting
"Finish four things by Monday 12:00 for a meeting with my supervisor" is a common pattern.
- **Fix:** add a "prepare for" target: choose a deadline, the items to cover, and buffer settings (extra time per item, plus one buffer session). The planner then lays out the sittings backwards from the deadline, which is what I did by hand in this session.

### 3.5 Weekly sittings cap
The plan for 28–30 Nov comes to 16 sittings over 3 days. Workable time is 750 min/day, but nothing warns when a day goes past a sustainable load.
- **Fix:** add a soft cap (for example 7 sittings/day). Warn when the plan goes over it, and show the plan's total hours against goal targets (Lit 6 h/wk, Impl 8 h/wk).

### 3.6 Meeting notes on supervisor meetings
- **Fix:** link a meeting block to an agenda generated from the week's paper notes, tasks done and open questions. Afterwards, capture action items and turn them into tasks.

## 4. Smaller fixes

- **Up next, after the evening cutoff:** it suggested "Review 3 due items" at 17:35 even though nothing work-related was planned after 18:00. Up next should respect the light and evening windows.
- **Implementation goal:** 8 h/week has had zero blocks this week, and nothing flagged it. Add a goal-pace warning mid-week.
- **`builtDay` side effect:** adding a block to a future date silently creates that day's plan. Make this explicit, or allow building a day without pushing it to the calendar.
- **Duplicate calendar events for a task and its block** *(found 2026-11-28)*: adding the hostel-office task (due Mon) and a block linked to it pushed two Google Calendar events for the same errand. When a task has a block linked to it, push only the block.
- **Titles:** generated titles such as "Marty et al. 2019, 'Snap: …' (ACM SOSP) — the network stack used" contain citation text. Store a clean title and keep the citation in a separate field.

## Suggested order

1. Fix 1.1, 1.2 and 1.4 (wrong numbers erode trust in Workload).
2. Add paper objectives to `add_block` (2.1) and batch operations (2.2). These are the biggest wins for planning from chat.
3. Add the day-shape preference (3.1) and hard-deadline alerts (3.2).
4. Add recurring commitments (2.3) and tentative meetings (2.4).
5. Build the "prepare for" planner (3.4).
